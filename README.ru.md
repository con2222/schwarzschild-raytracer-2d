# 2D Schwarzschild Black Hole Ray-Tracer

Интерактивный симулятор релятивистской физики и эффектов гравитационного линзирования в окрестностях статической черной дыры. Проект написан на **C++17** с использованием **OpenGL** и визуализирует, как сильное гравитационное поле искривляет траектории световых лучей (фотонов) в соответствии с общей теорией относительности Эйнштейна в метрике Шварцшильда.

## Сценарии симуляции

Движок последовательно запускает три различных физических сценария, распределенных по таймлайну:

1. **Photon Orbiting (Старт на 0 кадрах):** Демонстрирует критическое поведение света на границе фотонной сферы. Фотон запускается по касательной и непрерывно вращается вокруг горизонта событий.
2. **Point Source Rays (Старт на 180 кадрах):** Пучок световых лучей излучается из одного точечного источника (например, далекой звезды или зонда). Это наглядно показывает эффект разделения пучка: часть лучей падает в сингулярность, часть огибает ее, а остальные улетают с сильным отклонением.
3. **Parallel Rays / Гравитационное линзирование (Старт на 360 кадрах):** Плоский фронт параллельных лучей эмулирует свет, приходящий от бесконечно удаленного астрономического объекта. Проходя мимо черной дыры, лучи фокусируются и искажаются, демонстрируя классическое гравитационное линзирование.

## Кастомизация и эксперименты (`constants.h`)

Вы можете полностью изменить физику, геометрию экрана и производительность симуляции, не затрагивая основной код движка. Откройте `constants.h` и настройте значения внутри пространств имен:

```cpp
namespace Physics {
    const float c{ 1.0f };       // Скорость света
    const float G{ 1.0f };       // Гравитационная постоянная
}

namespace BlackHole {
    const float rs{ 1.0f };      // Радиус Шварцшильда
    const float MASS{ 0.5f };    // Масса черной дыры
}

namespace Visual {
    const int NUM_STARS = 200;            // Количество звезд на заднем фоне
    const int WIDTH = 1920;               // Разрешение окна по ширине
    const int HEIGHT = 1080;              // Разрешение окна по высоте
    const float VIEW_WIDTH = 8.0f;        // Граница ортографической проекции по X
    const float VIEW_HEIGHT = 6.0f;       // Граница ортографической проекции по Y
    const float POINT_SOURCE_X = -7.6f;   // Координата X точечного источника света
    const float POINT_SOURCE_Y = 5.1f;    // Координата Y точечного источника света
    const int CIRCLE_SEGMENTS = 100;      // Качество отрисовки окружностей (дискретизация)

    // Триггеры сценариев на таймлайне (в кадрах)
    const int ORBITING_START = 0;         
    const int POINT_SOURCE_START = 180;   
    const int PARALLEL_START = 360;       
}

namespace Simulation {
    const float minStep{ 0.01f };         // Минимальный шаг интегратора (вблизи горизонта)
    const float maxStep{ 0.1f };          // Максимальный шаг интегратора (на удалении)
    const float transitionStart = 1.0f;   // Радиус, где завершается оптимизация шага
    const float transitionEnd = 10.0f;    // Радиус, где начинается оптимизация шага
    const float MAX_DISTANCE = 16.0f;     // Радиус, после которого луч считается улетевшим (Escape)
    const float INTEGRATION_STEP = 0.05f; // Расстояние, преодолеваемое лучом за один кадр
}

```

### Что можно попробовать:

* **Кинематическая плавность (`INTEGRATION_STEP`):** Уменьшите это значение (например, до `0.01f`) для ультраплавной, кинематографичной отрисовки траекторий или увеличьте для мгновенного просчета путей лучей.
* **Пересечение таймлайнов:** Установив `POINT_SOURCE_START` и `PARALLEL_START` в значение `0`, вы можете заставить все сценарии работать одновременно прямо с момента запуска, создавая массивную сетку взаимодействующих световых векторов.
* **Плотность лучей:** Чтобы настроить общее количество генерируемых лучей света, просто измените количество итераций в циклах `generatePointSourceRays` и `generateParallelRays` внутри файла `main.cpp`.

## Архитектура проекта

Исходный код проекта опирается на модульную архитектуру:

* `constants.h` — централизованный конфигурационный файл, содержащий все физические, математические и визуальные параметры.
* `ray.h` / `ray.cpp` — объявляет структуру данных `Ray`, которая отслеживает историю координат луча (его трейл), состояние выполнения и высокоуровневые границы интеграции.
* `physics.h` / `physics.cpp` — ядро численных расчетов (вычисление релятивистских ускорений, шаги Верле и адаптивные ограничения).
* `rendering.h` / `rendering.cpp` — графический движок `RenderEngine` на базе OpenGL, инкапсулирующий управление окном GLFW, буферизацию кадров и базовые операции отрисовки вершин.
* `main.cpp` — точка входа в приложение, координирующая последовательность сценариев и управляющая главным циклом выполнения программы.

## Сборка и запуск

### Зависимости

Проект является кроссплатформенным. Системные зависимости удобно управляются через менеджер пакетов **vcpkg**:

```bash
vcpkg install glfw3 glew glm
```

### Сборка через консоль (CMake)

1. Склонируйте репозиторий:

```bash
git clone https://github.com/con2222/schwarzschild-raytracer-2d.git
cd opengl-blackhole
```

2. Сконфигурируйте проект, указав путь к локальному toolchain-файлу vcpkg:

```bash
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="D:/vcpkg/scripts/buildsystems/vcpkg.cmake"
```

3. Скомпилируйте исполняемый файл:

```bash
cmake --build build
```
